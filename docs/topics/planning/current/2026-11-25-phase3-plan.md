**Mandatory two-commit pattern for every extraction layer** (mirrors Phase 1 §§3–7):

1. **Commit A — characterization only.** Add tests that pin the exact current behaviour of
   every function about to be moved/created/changed, including query counts. Backend: produce
   a coverage JSON and prove 100% of the original functions with
   `python3 scripts/check_branch_coverage.py --coverage coverage-original.json --base HEAD
   --require-file … --require-function …` (Phase 1 plan §3). Frontend: temporarily put the
   *original* file in the `vitest.phase3.config.*` threshold glob and run
   `npm --prefix <app> run test:phase3` at `branches: 100` for that file (PROVISIONAL P5, §18).
2. **Commit B — the move.** Move the functions unchanged into the new module, add re-exports
   so every importer (Django `urls.py`, React imports) still resolves, switch the coverage
   scope from the old file to the new module, update the tests' imports. The diff-scoped gate
   must be green again at 100% branches. No inline edit of unrelated code, no cleanup, no
   rename of behaviour in the same commit.

**Per-layer verification (all required before the PR is submitted):**

- Backend: backend HTML/API equivalence report — zero diffs, noise floor first; unchanged
  query counts; `pytest` for the touched shards; `black .`.
- Frontend: frontend journey report — zero diffs; app `npm run test:run`, `npm run eslint`

### 3.3 Journeys (`scripts/equivalence/frontend/`, Python + Playwright)

Playwright is already a repo test dependency (`.circleci/continue.yml:89-103` installs
Chromium); the harness stays stdlib+Playwright Python so it shares the backend normalisers and
report renderer. Layout:

```
scripts/equivalence/frontend/
  runner.py            # CLI, two browser contexts, invokes journeys, renders report, exit code
  capture.py           # per-step network + DOM/ARIA capture and normalisation
  journeys/
    scorecard_v2_tracking.py
    scorecard_v2_gamesetup.py
    designer_gametable.py
    officials_pages.py
    passcheck.py
    liveticker.py
  tests/                # captured-trace fixtures; 100% branch coverage of capture.py
```

- `runner.py` mirrors `scripts/equivalence/runner.py`: `--ref`, `--cand`, `--username`,
  `--password`, `--report`, `--run-id`, `--comment-pr`, `--journeys`, `--intended`. It creates
  one fresh browser context per side (basic auth + Django role login with the same env names
  as `manifest.json:3-17`), runs each journey on ref and cand, diffs them step by step,
  reuses the redacted report shape (`report.py:49-133`) with a journey section, and exits 1 on
  any unexplained diff (`runner.py:157`). No journey is trusted before the ref-vs-ref noise
  floor passes with all four role credentials.
- **Journeys (same steps on both sides):**
  1. `scorecard_v2_tracking` — open a run-id-tagged game in the tracking screen, wait for
     mount, record one play (touchdown + try), undo it, assert log/score; capture each step.
  2. `scorecard_v2_gamesetup` — open the setup screen for that game, fill crew slots, start the
     game; capture DOM/ARIA before and after.
  3. `designer_gametable` — open a run-id-tagged designer gameday, edit a team cell, save;
     capture row text/ARIA and the PUT body.
  4. `officials_pages` — `/officials/`, sign-up list/add guard, official profile licence view
     as the `official` role (Moodle-gated guard, as in `scenarios.py:13-17`).
  5. `passcheck` — passcheck view for the run-id game; captured eligibility list.
  6. `liveticker` — public `/liveticker/` page and its XHR sequence; **exclude the SSE stream**
     (`/api/liveticker/stream/`) exactly as the backend harness does (Phase 2 plan §5).
- **Per-step capture and diff (the two required artefacts):**
  - **Normalised network requests**: ordered `[{method, path, body_shape}]` for every
    XHR/fetch to `/api/…`. Path query params sorted; run-id ids replaced with `<entity-N>`;
    `body_shape` is key/type structure only, **never values** (same redaction rule as
