# Phase 1 implementation plan (agreed, 2026-11-25)

This file is self-contained. It is the only brief the implementing session needs for Phase 1,
besides the [roadmap](./2026-11-25-architecture-remediation-roadmap.md). All decisions are final.

Tracking issue: [#2537](https://github.com/dachrisch/leaguesphere/issues/2537).
Format and level of detail follow the [Phase 0 plan](./2026-11-25-phase0-plan.md).

## 0. Ground rules

- Work in a worktree based on this plan's branch `phase1-plan-docs`; never commit to `master`.
  If the worktree path or a layer branch already exists, **stop and report**; do not overwrite.
- All commits are signed (`git commit -s`), conventional, one logical change each. DCO rejects
  unsigned commits (root `AGENTS.md:277-281`).
- PRs are a `gh stack`, **ready for review (`--open`), never drafts**. The agent **never merges**;
  the user merges bottom-up (roadmap:77; Phase 0 plan:11-12).
- Required CI contexts: `full_gate`, `scope_coverage`, `check_version_sequence`
  (Phase 0 plan:13). **`codecov/project` is not required and will dip once when `branch = True`
  is enabled** — say so in the Layer 1 PR body; it does not block.
- `python3 scripts/check_scope_coverage.py` must pass after every layer that adds tracked files
  (stdlib script, no `uv`; Phase 0 plan:14). New `scripts/**` files are covered by the
  `(tests|scripts)/.*` rule (`.circleci/scope-mapping.txt:95`); docs are excluded
  (`.circleci/scope-exclude.txt:9`), so no scope-mapping change is expected.
- Module guides are authoritative: root `AGENTS.md`, `gamedays/AGENTS.md`, `league_table/AGENTS.md`,
  `gameday_designer/AGENTS.md`, `officials/AGENTS.md`, `passcheck/AGENTS.md`, `liveticker/AGENTS.md`.
  Root `AGENTS.md` already lists the boundary check at `:260`; update it in Layer 1 to also name
  the branch-coverage check.
- **Boundary:** `gamedays` must import none of `league_table`, `gameday_designer`, `officials`,
  `passcheck`, `liveticker`; `gameevents` stays allowed (roadmap:36; checker:45-56). Done =
  `scripts/app_boundary_allowlist.txt` has **zero** entries for those five apps and the
  equivalence report is clean. No schema migrations in Phase 1 (roadmap:38, decision 2 at :56).
- **Stale-entry rule:** each layer deletes its own allowlist lines in the *same* PR; unknown and
  stale entries both fail (`scripts/check_app_boundaries.py:207-236`;
  `scripts/app_boundary_allowlist.txt:11-12`). `python3 scripts/check_app_boundaries.py --root .`
  must be green after every layer.
- **Inversion, never hiding:** no `apps.get_model("<forbidden app>", …)`, no dotted
  `get_model("<app>.<Model>")`, no `importlib.import_module("<forbidden app>…")`, no function-body
  import, no moving a back-edge to another module. The Layer 1 checker enforces all of these,
  including inside nested calls (`ast.walk`, `check_app_boundaries.py:142`).
- **Behaviour:** characterization tests first; no intended diffs in any equivalence report. The
  runner exits 1 on unexplained diffs (`scripts/equivalence/runner.py:157,168-171`) and reports
  are redacted (README:49-54). Ref-vs-ref noise floor must be zero and must be run with all four
  harness role credentials present (README:14-24,42-47).
- **Query counts:** every new/changed DB-touching view or function keeps an exact
  `assertNumQueries`; counts must not grow (root `AGENTS.md:205-211`; `gamedays/AGENTS.md:48-51`).
- **Stage, base SHA — step 0, no hard-coded SHA:** at implementation start determine the base as
  the **full SHA of current `origin/master`** (`git fetch origin && git rev-parse origin/master`)
  and record it in the stack PR bodies. Rebuild the phase baseline from that full SHA *before*
  the first layer's report:
  `gh workflow run deploy.yaml --ref master -f agent_candidate_ref=<full base sha> -f agent_tag=agent-ref`
  (Phase 0 plan:138-153; roadmap:49). `cand` follows `agent-candidate` automatically through the
  `ls-agent-cand-update` system timer (~5 min); the coordinator reapplies `ls.agent.stage` on
  servyy-test. **Never re-run `ls.app.stage` or `ls.db.sync` during the phase** (Phase 0 plan:176,182;
  roadmap:50). No migration may be in the base (`git diff --name-only <stage image sha>..<base> | grep migrations`
  — Phase 0 plan:152-153).
- **Verified facts at planning time** (`origin/master` was `96ec02b17`): the checker prints
  `15 files, 39 statements: league_table=17, gameevents=8, gameday_designer=4, officials=4,
  passcheck=3, liveticker=3 (… 31 allowlisted)`; those 31 entries are
  `scripts/app_boundary_allowlist.txt:17-47` in 14 files (the 15th is gameevents-only
  `gamedays/service/gamelog.py:8`). **Re-run the checker at implementation start and reconcile
  before relying on these counts.** Corrections to prior docs: the second kept FK is
  `GameOfficial.official → "officials.Official"` (`gamedays/models.py:267-271`), not
  `Gameinfo.official`; `Gameinfo.league_group → "league_table.LeagueGroup"` is at
  `gamedays/models.py:212-214`. Both are string references, documented, not modelled by the checker.

### 2.2 Coverage gate (GREEN)

1. **`.coveragerc`**: add `branch = True` under `[run]` (currently `:2-3`). Keep omissions at
   `:4-24` — notably `*apps.py`, `*/urls.py`, `*/tests/*`, migrations. This is why all hook
   registration lives in `<app>/service/gamedays_hooks.py::register()`, never in `apps.py`.
2. **Create `scripts/check_branch_coverage.py`** — stdlib only (`argparse`, `json`, `pathlib`,
   `re`, `subprocess`, `sys`), runnable with `python3`. Contract:
   - Args: `--coverage <coverage.json>` (required), `--base <ref-or-sha>` (default `origin/master`),
     optional `--shard <cov_flag>`, optional repeatable `--require-file <path>` /
     `--require-function <qualified-name>` for local pre-move verification.
   - Merge base: try `git merge-base <base> HEAD`; if that fails, treat `<base>` as the merge
     base. Changed files: `git diff --name-only <merge-base> --` plus `git ls-files --others
     --exclude-standard` (untracked new files locally).
   - Scope: changed `*.py` files, excluding **every** `[report] omit` pattern from `.coveragerc`
     — parse the file with `configparser` and match with `fnmatch` (this covers `*/manage.py`,
     `*/settings.py`, `*/wsgi.py`, `*/asgi.py`, `*apps.py`, `*/urls.py`, `*/tests/*`,
     `*/fixtures/*`, `*/static/*`, `*/templates/*`, migrations and `__init__`, not just a subset).
     Repo-root `*.py` (`conftest.py`, `test_settings.py`, `manage.py`) and `.claude/**.py` have no
     shard owner and are **ignored**; any other unmapped changed `.py` fails loudly (below).
     A function is in scope if its file is new, or if any added line from
     `git diff --unified=0 <merge-base> -- <file>` falls inside it. coverage.py 7.17 emits a
     `""` function for module-level code, and that entry also owns each function's `def` and
     decorator lines: **skip the `""` entry entirely** and map each added line to the innermost
     function whose span contains it; for a changed `def`/decorator line use the AST of the head
     file so the function below is scoped (a def-line-only edit must not escape the gate).
     Function lines = `executed_lines ∪ missing_lines ∪ excluded_lines ∪` branch endpoints from
     that function's `functions` entry.
   - Ownership map (prevents one shard judging another shard's functions):
     `gamedays|league_table|gameevents` → `python-gamedays`;
     `officials|teammanager|accounts` → `python-officials`;
     `liveticker|scorecard|scorecard_v2` → `python-live`;
     `passcheck|gameday_designer|journey|matchreport` → `python-designer`;
     `league_manager|home|dbaccess|share` → `python-core`;
     `scripts|tests` → `python-cross`. Any changed `.py` that is neither omitted/ignored nor
     mapped → **fail loudly** with "add an ownership mapping" (scope mapping at
     `.circleci/scope-mapping.txt:44-96` guarantees the owning shard runs).
   - Read `files[].functions` from coverage.py JSON (`coverage json`, produced by
     `--cov-report=json:coverage.json`); a file in scope but absent from the JSON fails with
     "no branch data" (forces tests to import it). Any function with non-empty
     `missing_branches` fails with file, qualified function name and branch line pairs.
   - `# pragma: no branch` / `# pragma: no cover` is allowed **only** with an inline reason on
     the same line (e.g. `# pragma: no cover -- Django app registry side effect`). Print every
     pragma found in scope; a reasonless pragma fails.
   - Exit 1 on any failure, 0 otherwise; print `N functions in scope, M files, 0 missing branches`.
3. **CI wiring in `.circleci/continue.yml`**: the shared `python_shard_test` currently runs
   `uv run pytest … --cov=. --cov-report=xml --cov-report=html` at `:174` and uploads `coverage.xml`
   at `:177-179`. Add `--cov-report=json:coverage.json` to that pytest command (`:174`) and insert
   the following new `- run:` step after it, before `store_test_results`/`codecov/upload`:

```yaml
      - run:
          name: Branch coverage of changed functions (<< parameters.cov_flag >>)
          command: |
            git fetch --no-tags origin master:refs/remotes/origin/master
            python3 scripts/check_branch_coverage.py \
              --coverage coverage.json --base origin/master \
              --shard << parameters.cov_flag >>
```

   No workspace combine or `full_gate` wiring is needed: ownership mapping makes each shard
   authoritative for its own files.

   **Base = merge base with `origin/master`, never `<< pipeline.git.base_revision >>`.**
   Scoped CI itself diffs against master (`.circleci/config.yml:88`, `base-revision: master`), so
   the gate must use the same base. `pipeline.git.base_revision` is the commit *before the latest
   push*, so a layer pushed in several commits would only have its last push checked. For a
   stacked PR the diff against master also includes the lower layers' functions. That is
   intended: they were already held to 100% and must stay there. The explicit `git fetch` makes
   sure `origin/master` exists in the CI checkout. On a tag pipeline at master's tip the diff
   is empty, and the gate reports 0 functions in scope and passes.
4. **Root `AGENTS.md`**: add `python3 scripts/check_branch_coverage.py` to the Verification
   Checklist next to the boundary check at `:260`.

```bash
uv run pytest scripts/tests/test_check_branch_coverage.py scripts/tests/test_check_app_boundaries.py -v
uv run pytest gamedays/tests/test_hook_system_checks.py -v
python3 scripts/check_scope_coverage.py
```

Expected: all green; checker's own functions at 100% branch.

## 3. Layer 2 — `phase1-schedule-registry` (~260 lines; 4 entries removed)

**Goal:** replace the branching in `signals.py` with an ordered strategy registry; remove all four
`gameday_designer` imports.

**Files:** new `gamedays/service/designer_hooks.py`, `gamedays/service/schedule_strategies.py`;
modify `gamedays/service/{signals.py,placeholder_service.py,schedule_resolution_service.py,gameday_migration_service.py}`,
`gameday_designer/apps.py`, new `gameday_designer/service/gamedays_hooks.py`; allowlist.

**Approach (registry + move-to-owner):**
- `schedule_strategies.py`: `register(order, name, applies(gameday), resolve(instance))`; first
  match wins. Precedence **designer template → canvas → legacy** (`signals.py:21,30,37`).
  Canvas (`GamedayDesignerState`) and legacy (`ScheduleUpdate`) are gamedays built-ins; the
  designer registers a strategy that checks `TemplateApplication` and calls
  `GamedayScheduleResolutionService.update_participants` for standing and stage (`:22-29`).
  On failure, inside the existing broad `except` (`:43-47`) call **only**
  `logger.exception("schedule resolution failed strategy=%s gameinfo=%s", name, instance.pk, ...)`
  (traceback visible in Loki) — **no counter, no in-process metric** — and let finalisation
  succeed.
- `designer_hooks.py` slots implemented by `gameday_designer/service/gamedays_hooks.py::register()`:
  `template_for_gameday` (application first, `schedule_<format>` fallback —
  `placeholder_service.py:26-52`), `slots_for_template` (`:54-69`),
  `update_rules_for_template` / `update_rule_for_slot` (`schedule_resolution_service.py:29-35`;
  `gameday_migration_service.py:239-243,369-399`). (`has_template_application` is dropped: nothing
  calls it.) Duck-typed slot/rule objects cross the registry; gamedays keeps its
  pandas/placeholder orchestration because `GamedayPlaceholderService` is consumed by passcheck
  and gamedays serializers (`passcheck/api/serializers.py:11,126-138`;
  `gamedays/api/serializers.py:20,311`; `gamedays/service/gameday_service.py:403`). Registration
  only from `GamedayDesignerConfig.ready()`. The designer-template strategy is a **required hook
  covered by the `phase1.E001` system check**: an installed `gameday_designer` without it fails
  `manage.py check` in CI and `migrate` on deploy, and `get()` raises `ImproperlyConfigured` at
  call time. There is **no third fallback** — a gameday with a `TemplateApplication` must never
  silently resolve through the canvas or legacy strategy.

**Removes:** `signals.py` (allowlist:35), `placeholder_service.py` (:33),
`schedule_resolution_service.py` (:34), `gameday_migration_service.py` (:24).

**Tests first (two commits):**
1. Characterization-only commit: `gamedays/tests/service/test_schedule_strategy_characterization.py`
   pins today's precedence and all three fallbacks; extend `gamedays/tests/service/test_signals_dual_logic.py:22-56`;
   full-plan assertion in `gamedays/tests/service/test_gameday_migration_service.py`. Verify with
   `uv run pytest <those files> --cov=gamedays/service/signals.py --cov=gamedays/service/placeholder_service.py
   --cov=gamedays/service/schedule_resolution_service.py --cov=gamedays/service/gameday_migration_service.py
   --cov-report=json:coverage-original.json` and
   `python3 scripts/check_branch_coverage.py --coverage coverage-original.json --base HEAD
   --require-file … --require-function …` — **every original function about to be changed must
   show 0 missing branches before the move commit**.
2. Move commit: `gamedays/tests/service/test_schedule_strategy_registry.py` adds precedence with
   all three strategies present, no-hook fallback, idempotent re-registration, and a failing
   resolver that logs with `exc_info` and strategy name + gameinfo id while `save()` succeeds;
   `test_designer_hooks_query_parity.py` pins identical slot/rule results with `assertNumQueries`.
   After the move, the diff-scoped gate requires 100% branch coverage again.

**Equivalence:** `finalize-game`, `finalize-canvas`, `finalize-legacy`; gameday detail and games
APIs for designer-template/canvas-published/completed (`manifest.json:53-58`); designer-publish
scenario (`scenarios.py:129-149`).

**Risks/rollback:** precedence drift and query growth (pinned by tests); a partial revert of only
