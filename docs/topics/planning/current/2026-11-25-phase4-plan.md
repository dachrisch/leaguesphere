- Module guides are authoritative: root `AGENTS.md`, `passcheck/AGENTS.md`,

## 3. Target design of `packages/ls-client`

The package is the single source of truth for the HTTP contract. It is deliberately small; it is
**not** a component library and it does not absorb `trackEvent.ts` (§17 P10).

- `packages/ls-client/package.json` — plain name `ls-client` (no npm scope, no workspaces),
  `"type": "module"`, `exports`/`types` pointing at the consumed entry, scripts `test:run`,
  `test:coverage`, `typecheck`, `eslint`, and optionally `build` if the spike selects prebuilt
  output (§17 P2).
- `src/index.ts` — public exports only: `createClient`, `LsApiError`, `readToken`, `writeToken`,
  `createAuth`, types `ClientConfig`, `RequestOptions`, `TokenSources`.
- `src/http.ts` — one typed request core (`get`/`post`/`put`/`patch`/`delete`), with configurable
  `baseURL`, headers, `credentials`, CSRF cookie/header names, body serialisation and a
  per-request header override. **It must emit byte-identical request signatures to the client it
  replaces**; each app layer pins those signatures in characterization tests (§15.1).
- `src/error.ts` — one error type, `LsApiError { status, message, detail, body,
  retryAfterSeconds }`, covering today's four shapes: passcheck's `{message}`,
  `AxiosError`-based rethrows, `HttpError {status,retryAfterSeconds}`, journey's generic `Error`
  and v2's `ApiError {status,body,detail}` (§15.2).
- `src/auth.ts` — canonical key `token`, dual-read `localStorage.getItem('token') ??
  localStorage.getItem('authToken')`, `writeToken()` writes **only** `token`, `clearToken()`
  removes **both** (so logout cannot leave a stale `authToken`). Configurable `onUnauthorized`
  callback preserves each app's 401 policy exactly (§15.2).
- `src/index.test.ts`, `src/http.test.ts`, `src/error.test.ts`, `src/auth.test.ts` — vitest with
  `provider: 'v8'` and `thresholds: { branches: 100, functions: 100, lines: 100, statements: 100 }`.
- `vitest.config.ts`, `tsconfig.json`, `eslint.config.mjs`, `README.md` — the package's own config
  so it can be tested and linted standalone; the README records transport/auth/error decisions.

### 3.1 Where the old client stays during migration

Each app layer keeps its old client file (or its Redux action file) and changes **one import or
one re-export line** to select `ls-client` (`USE_LS_CLIENT = true`). That line is the documented
one-line rollback: flipping it restores the old client without a revert. The deletion layer (§14)
removes both the old files and the switch.

### 3.2 Per-app error shims

Where an app's visible behaviour depends on a different error shape (passcheck throws a plain
`{message}` object; Redux apps dispatch `returnErrors`), a small adapter in the app translates
`LsApiError` to the existing shape. The adapter is part of that app's migration layer, is covered
to 100% branches, and is deleted together with the old client in Layer 10 so the end state really
is **one error type**.

## 15. Hard-spot designs

### 15.1 Request-signature equivalence (the central risk)

The Playwright journeys diff the **network**, so a refactor that changes `Accept`, `Content-Type`,
`Authorization`, `X-CSRFToken`, `X-Scorecard-Device`, `credentials`, query order or body
serialisation fails even if the backend response is the same. Each app layer therefore:
(a) characterizes the exact request signature of every old client method, (b) configures the
package client to reproduce it, and (c) runs the app's journey against `www-ref`/`www-cand`.
The package's defaults are explicit, never library defaults, so axios→fetch migrations cannot
silently drop or add a header.

### 15.2 Auth, dual-read and 401

`readToken()` = `localStorage.getItem('token') ?? localStorage.getItem('authToken')`; both keys
are read on every authenticated request during migration. `writeToken()` writes `token` only;
`clearToken()` clears both. 401 policy is injected, not global: passcheck production redirect +
dev alert (`passcheck/src/utils/api.ts:40-52`), designer redirect (`gamedayApi.ts:57-60`,
`designerApi.ts:134-137`), journey throw, v2 no-token session path, share anonymous. Every policy
is exercised by a browser journey with an expired/invalid token, including the DOM side effects
(redirect target or alert text).

### 15.3 Dockerfile / CI / scope plumbing

- One `COPY packages/ls-client /packages/ls-client` in the `node-builder` stage serves all seven
  one-level-deep app dirs (`container/nginx.Dockerfile:57-118`). `npm ci` symlinks the package;
  verify Vite resolution once in the spike, then in every app layer.
- GHA `cache-dependency-path` must include `packages/ls-client/package.json`; CircleCI's
  `node/install-packages` with `app-dir:` already sees the full checkout but its cache key should
  be checked in the spike.
- Scope rules in Layer 1 map `packages/ls-client/.*` to all seven frontend jobs + `run-images`
  so a package-only commit can never skip a consumer's tests or the image build.

### 15.4 "No workspaces" and packaging decision

Decision 8 is final: spike first, then `file:`. This plan introduces **no root `package.json` and
no `workspaces` key**. If `file:` fails, §17 P0 is the only permitted alternative and requires a
user decision recorded in the ADR; it is not silently substituted.

### 15.5 Frontend diff-scoped branch gate (**PROVISIONAL P5**)

App-wide 100% thresholds would fail on untouched code, so: the package itself uses vitest v8
`thresholds` (100%), and `scripts/check_frontend_branch_coverage.py` judges only changed/new TS/JS
functions, using v8/istanbul JSON and a per-app ownership map. Pre-move characterization uses
`--base HEAD --require-file … --require-function …`, mirroring Phase 1's Python gate. If the
coordinator prefers a simpler mechanism (per-app threshold files scoped with an `include` to the
changed modules), replace this script in Layer 2 and record the decision.
