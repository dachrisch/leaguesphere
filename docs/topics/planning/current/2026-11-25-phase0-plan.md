# Phase 0 implementation plan (agreed, 2026-11-25)

This file is self-contained. It is the only brief the implementing session needs for Phase 0.
Roadmap and decisions: [2026-11-25-architecture-remediation-roadmap.md](./2026-11-25-architecture-remediation-roadmap.md).

## 0. Ground rules

- The layer-0 branch `phase0-docs` already exists and is pushed. Work in a worktree; never commit to `master`.
- All commits are signed (`git commit -s`), conventional, and one logical change each.
- PRs are a `gh stack`, **ready for review (`--open`), never drafts**. The agent never merges; the user merges bottom-up. The 0b PR must be merged with a **merge commit**.
- Non-interactive `gh stack` setup: `git config rerere.enabled true`, `git config remote.pushDefault origin`. Always pass branch names to `init`/`add`, `--auto` to `submit`, `--json` to `view`. If `gh stack view --json` reports that `master` belongs to multiple stacks, check out a non-trunk branch first (`gh stack checkout <branch-or-pr>`; use `gh stack unstack --local` only if local/remote compositions conflict).
- CI required contexts (per `docs/topics/deployment/scoped-ci.md:62-64`): `full_gate`, `scope_coverage`, `check_version_sequence` — cited from docs, not a live ruleset inspection.
- **`python3 scripts/check_scope_coverage.py` must pass** after every layer that adds tracked files. It is a stdlib script; do not run it with `uv`.
- Module guides (e.g. `gamedays/AGENTS.md`, `league_manager/AGENTS.md`) and root `AGENTS.md` are authoritative; read them before touching a module. Root `AGENTS.md` must be updated in the same change as new behaviour.

## 3. Layer 0c — `phase0c-equivalence` (behaviour equivalence)

**Goal:** prove that every later refactor behaves the same. One long-lived agent stage on `servyy-test.lxd`, one restore, one credential — no per-run reset or secret handoff. One DB shared by `ref` (master image at phase start, no watchtower label) and `cand` (stack head). Read probes diff the same data; write scenarios create fresh run-id-tagged entities on each side and diff the resulting reads with IDs normalised. A phase needing a schema migration cannot share the DB — flag it in that phase's plan and provide a second DB copy.

### 3.1 Repo-side commits (this stack)

**0c.1 — Probe suite and noise floor. Create `scripts/equivalence/`:**
- `manifest.yaml` (or `.json`): coverage-based sample, not a count — at least one gameday per schedule type (designer template, canvas-published, legacy JSON), with and without officials, finished and upcoming, plus league tables for those leagues/seasons. Requests are HTML pages and `/api/` endpoints, grouped by role (anonymous, staff, team manager, official).
- `normalise.py`: strip/normalise CSRF tokens, timestamps, asset hashes, ETags, session-specific bits and run-id entity IDs.
- `diff.py`: structural JSON diff plus normalised-text HTML diff.
- `selftest.py`: ref vs ref must produce **zero diffs**; this validates the normaliser before anyone trusts a report.
- Tests under `scripts/equivalence/tests/`.
