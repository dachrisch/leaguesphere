### 3.2 Approach

`python3 scripts/check_query_assertions.py --base origin/master [--root .] [--global]
[--report-only]`. Stdlib only (`argparse`, `ast`, `datetime`, `pathlib`, `re`, `subprocess`, `sys`),
runnable with `python3`, no `uv`.

- **Merge base:** try `git merge-base <base> HEAD`; on failure treat `<base>` as the merge base
  (same fallback as Phase 1's `check_branch_coverage.py`). Changed files = `git diff --name-only
  <merge-base> -- '*.py'` plus `git ls-files --others --exclude-standard -- '*.py'`. With
  `--global`, use all tracked `*.py` instead.
- **Test-file scope:** path contains a `tests/` component, or basename matches `test_*.py` /
  `*_test.py`. Non-test files are never judged. Functions: module-level `def test_*` and `test_*`
  methods of classes whose base names contain `TestCase` but not `SimpleTestCase` (APITestCase,
  TransactionTestCase count). Use `ast.parse` per file; an unparseable file fails loudly with the
  path and error.
- **DB-touch evidence (static heuristic):** a `pytest` fixture argument named `db`, `django_db`,
  `transactional_db`, `client`, `django_assert_num_queries` or `assert_num_queries`; a
  `@pytest.mark.django_db*` decorator; a `TestCase`-family base class; or an attribute/call in the
  function body matching `self.client.<verb>`, `.objects.`, `Client(`, or one of the assertion
  names. A function with none of these is not DB-touching and is skipped. `ast.walk` the function
  body but **exclude nested `def` subtrees**, so an assertion in a helper cannot satisfy the test
  (pinned by tests).
- **Accepted assertions:** `self.assertNumQueries(...)`, bare `assertNumQueries(...)` (the
  conftest context manager at `conftest.py:17-50`), `django_assert_num_queries(...)` and
  `assert_num_queries(...)` (fixture at `conftest.py:54-57`). The last two aliases are a
  PROVISIONAL decision (§17 P2) documented in the checker's help text.
- **Reasoned marker:** either a comment on the line immediately preceding the `def` (same indent)
  of the exact form `# query-assertion-exempt: <non-empty reason>`, or a decorator
  `@pytest.mark.query_assertion_exempt("<non-empty reason>")` (registered in `conftest.py:73-77`
  in this layer). A reasonless marker **fails**. Every exemption and its reason is printed in the
  report; PR bodies must list them for review. The existing `skip_query_check` marker is **not**
  an exemption (it carries no reason and no implementation) — the docs layer reconciles that text.
- **Cutoff handling:** `scripts/query_assertion_global_cutoff.txt` holds either `PENDING` or an
  ISO date. `--global` refuses to run while it is `PENDING`, on an invalid date, or before the
  date, with a clear message; `--report-only` ignores the cutoff (inventory use) and never fails.
  Layer 1 tests all these branches; Layer 8 is the only caller that uses `--global` in CI.
- **Output/exit:** `N test functions in scope, M DB-touching, K asserted, E exempted (reasons
  printed)`; exit 1 on any DB-touching unasserted and unexempted test, 0 otherwise.

CI step in `scope_coverage` (always-on, keeps the required-context set at three — §17 P10):

```yaml
      - run:
          name: Query assertions on changed test files
          command: |
            git fetch --no-tags origin master:refs/remotes/origin/master
            python3 scripts/check_query_assertions.py --base origin/master
```

- **Cutoff:** the date lives in the repo, the checker enforces it, and the last layer is labelled;
